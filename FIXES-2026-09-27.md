## 4. 🏷️ KATEGORIE + 🛍️ KATALOG — echtes Setzen (nicht mehr „nicht unterstützt")

**Ursache gefunden** (Baileys issue #2717, live nachvollzogen): WhatsApp
beantwortet `w:biz`-SETs für manche Felder **gar nicht** — kein `<error>`, kein
`<iq type="result">`, nur Stille. Unser Code hat auf eine Antwort gewartet, ist
nach 6s in ein Timeout gelaufen und hat das als **Fehler** gewertet — obwohl die
Kategorie längst gesetzt war. **Ein Timeout ist hier kein Beweis für Scheitern.**

### Kategorie — neuer Weg: Feuer-und-Vergessen + Rücklesen
1. `getBusinessProfile()` zurückslesen → steht sie schon? → fertig (nichts senden)
2. sonst **6 Node-Formen** per `sock.sendNode()` (wartet auf keine Antwort →
   Setup hängt nie): `categories`, `v:"244"`, `<profile>`-Wrapper, direkte
   `<category>`, deutsche Schreibweise, `<category id="…">`
3. 2s warten, dann **Rücklesen als Beweis** — nur das ist verlässlich
4. 10-Minuten-Cooldown zwischen Versuchen (kein Spammen bei Reconnects)

### Katalog — zwei Wege, der zweite ist neu
1. `sock.productCreate()` **mit** Antwort → Ergebnis verifiziert (wie vorher)
2. Server stumm → **Feuer-und-Vergessen**: exakt der Node, den `productCreate`
   intern baut (`product_catalog_add`), per `sendNode` ohne Warten. Jedes Produkt
   wird **genau einmal** gesendet — Merkliste `sent` in
   `Database/catalog-state.json`, damit Reconnects keine Duplikate bauen.
3. IQ-Probe weiter stündlich: antwortet der Server wieder, laufen die Produkte
   verifiziert durch.
